# Bubble
## Назначение
Основной сервис проекта Bubble <br>
Сервис взаимодействует с другим вспомогательными:
- [Users](https://github.com/mongolianpes/Bubble-Messenger-Server-Users) - управление пользователями, сохранение сессий, TLS
- [Messenger](https://github.com/mongolianpes/Bubble-Messenger-Server-Messenger) - обмен сообщений между пользователями, в том числе специальные сообщения для инициализации аудио диалога, окончания аудио диалога и передачи файлов
- [Files](https://github.com/mongolianpes/Bubble-Messenger-Server-Files) - сохранение файлов пользователей
- [AudioDialog](https://github.com/mongolianpes/Bubble-Messenger-Server-AudioDialog) - аудио диалог в реальном времени <br>
Для взаимодействия с сервисной частью имеется [Клиент](https://github.com/mongolianpes/Bubble-Messenger-Client)

## Функционал
- Принимает внешние запросы от пользователей, а после возвращает им информацию в формате json
- Для обработки запросов пользователей взаимодействует с соответствующими микросервисами по архитектуре оркестрации
- Сервис отвечает за расшифровку запросов, за исключением запросов TLS, регистрации и авторизации - расшифровка данных запросов лежит на сервисе Users
- В сервис встроен автоматический блокировщик IP адресов, блокирующий клиентов, которые слишком часто отправляет невалидные запросы

## Транспортная безопасность
При обращении через нестандартные порты (к этим портам обращаются [Клиент](https://github.com/mongolianpes/Bubble-Messenger-Server/blob/main/cmd/bubble/main.go)) применяются собственные механизмы шифрования. Обмен ключами и аутентификацияХэндлер /exchangekey позволяет обменяться с сервером общим секретом по алгоритму ECDH.

После обмена следует сразу использовать хэндлер /reg (если пользователь ещё не зарегистрирован), а затем /auth — для получения долгосрочного общего ключа, которым будет шифроваться передаваемые данные.

### Как работает шифрование
Механизмы шифруют:
- путь в URL
- тело запроса
<br>
Дополнительно они защищают от повторной отправки запросов злоумышленником:
- в каждом запросе передаётся время отправки и случайная строка
- сервер сохраняет случайную строку запроса на 30 секунд и отклоняет любые повторные запросы с этой же строкой в течение этого времени
- если с момента отправки прошло слишком много времени, запрос также отклоняется

### Что видит злоумышленник
Злоумышленник видит только то же, что и при обычном использовании HTTPS, плюс:
- информацию об устройстве (в захэшированном виде)
- остальные данные в зашифрованном виде (логин, пароль, тело запроса, время отправки, случайную строку)

## Переменные окружения
Для корректной работы необходимы переменные окружения:
- USERS_SERVICE_HOST_GRPC_PORT - адрес и порт сервиса Users
- MESSENGER_SERVICE_HOST_GRPC_PORT - адрес и порт сервиса Messenger
- FILES_SERVICE_HOST_GRPC_PORT - адрес и порт сервиса Files
- AUDIO_DIALOG_SERVICE_HOST_GRPC_PORT - адрес и порт сервиса Audio Dialog

## Сборка и запуск
Для запуска сервиса следует использовать Docker <br>
Установите Docker в случае если он не имеется <br>
Поменстить код репозиториев всех сервисов в одну директорию, в том числе основной. В данной директории разместите docker-compose.yml из директории docs данного репозитория. А также переместите директорию DB в корень. <br>
Запустите:
```
docker compose -d --build
```
